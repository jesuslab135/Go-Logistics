# Handoff — 2026-08-26

Two things happened today that a person picking this up needs to know: a branch
was written, and production was changed by hand. They are independent — the
production change is live now and does not wait for the branch.

## 1. Branch `feat/product-decisions-backend`

Fourteen commits off `main` (`ce7d063`), implementing the backend half of the
A/B/C product-decision set. **Not merged.** Each commit was checked out into a
throwaway worktree and confirmed to `go build ./...` and `go test ./...` green
on its own, `go vet ./...` clean.

`docs/2026-08-26_product-decisions-backend-plan.md` is the record: the decisions
and why, one section per item, and an implementation-status table at the end
mapping every item to its commit. Read it rather than the commit list — the
reasoning is the part that does not survive in a diff.

Two things it says that are easy to miss:

- **Six items are breaking for the frontend** (C1, C2, C3, B3, B2, C7). Each
  commit message states exactly what changed about the contract.
- **Migrations `000010`–`000017` have never been run against any database.**
  The `migrate` CLI is not installed on this workstation and the dev compose
  stack was down, so verification was build- and unit-test-only. This is the
  single largest untested surface on the branch. Running them against a scratch
  database is the first thing to do before merging.

### Not built, deliberately

The **service-reminder-due notification producer**. It needs something to notice
a date has passed, and this deployment is a single API container with no
scheduler. A due check that fired only when someone opened the notification bell
would be worse than none, because it would look like it worked. Everything else
in C9 shipped.

### Before this branch deploys

In this order — the first one locks people out if skipped:

1. **Grant a platform admin before deploying B9**, or `/api/v1/admin/*` closes to
   everyone including you: `docker compose run --rm cli platform-admin --email <you>`.
2. Create the private bucket and move existing receipts, signatures, inspection
   photos and media into it (B8 routes them by key prefix).
3. Run `docker compose run --rm cli inventory-drift` to see where the ledger and
   the stock rows disagree. Nothing is reconciled automatically, on purpose —
   the drift predates the fix and silently "correcting" it would destroy the
   evidence of how much there was.

## 2. Production: CORS now allows the Netlify frontend

The frontend at <https://go-logistics.netlify.app> could not call the API at
all: every browser request failed preflight because `CORS_ORIGINS` listed only
`http://localhost:5173` and the backend's own origin, which a browser never
sends. This was the open item in `deploy/README.md`'s known-follow-ups; it is
now closed.

Applied by hand on the VPS as `deploy`, backup at `/opt/fleet/.env.bak.cors`:

```
CORS_ORIGINS=https://go-logistics.netlify.app,http://localhost:5173,https://go-logistics.jesuslab135.com
```

then `cd /opt/fleet && docker compose up -d api`. Only the `api` container was
recreated. Verified live: the Netlify origin is echoed with `Vary: Origin`, an
unlisted origin still gets nothing, `/healthz` 200.

**This could not have gone through GitHub Actions.** The deploy workflow
excludes `.env` from the bundle on purpose — it also holds `POSTGRES_PASSWORD`,
`MINIO_ROOT_PASSWORD` and the JWT signing key, so it is server-owned and no
deploy can overwrite it. Config changes are an SSH edit by design; see
`deploy/README.md` under "Day-to-day".

If origins start changing often, the fix is to promote `CORS_ORIGINS` to a
GitHub **variable** (it is not a secret) and have `deploy.sh` write that one key
into `.env` per deploy, leaving the actual secrets alone. That makes the
allowlist reviewable in git. Not done — one origin has changed once.

## Open decision

**Netlify deploy previews are still blocked**, and will stay blocked. They are
served from `deploy-preview-<n>--go-logistics.netlify.app` — a different origin
for every PR — and `middleware.CORS` compares the `Origin` header exactly, so
there is no value that can be put in `.env` to cover them. Making them work is a
code change: suffix matching for a trusted domain, which widens the allowlist to
anything Netlify will serve under that name. Worth doing if previews are part of
review; not worth doing silently.
