## Findings

### F1 · MEDIUM — API-created employees are born inactive (DB defaults overridden by Go zero values)

`POST /api/v1/employees` without `"is_active": true` inserts `false` over the
column default `true`. **Confirmed live**: the created employee could not log in
and `cli setpass` refused it ("no active employee"). Same mechanism produced
`issue.state = ""` instead of `'OPEN'`. This is the known generator-wide
limitation (omitted columns with non-zero DB defaults get Go zero values), but
employee activation is the highest-impact instance: it silently produces
locked-out accounts through a supported endpoint.

**Fix plan**
- Files: `internal/http/dto/employee.go`, `internal/db/queries/employee.sql` (+ regen), then triage other resources.
- Change: make high-impact defaulted fields pointers in the Create DTO
  (`IsActive *bool`) and default them in the store (`if in.IsActive == nil { active = true }`),
  or use `COALESCE(sqlc.narg(is_active), true)` in the INSERT. Same treatment for
  `issue.state`/`source_type`/`asset_type` and any column found by scanning
  `000001_init.up.sql` for non-zero defaults on exposed resources.
- Regression test: handler-level — create employee without `is_active`, assert
  the row is active; create issue without `state`, assert `OPEN`.
- Blast radius: per-resource DTO+query+gen; start with `employee` and `issue`,
  then sweep.

### F2 · LOW — README not updated for session 2

The README documents session 1 well (authorization tables, upload validation,
bootstrap) but predates session 2: the bootstrap section says only the
`Administrador` role is created (now also `Almacén`), and there is no mention of
`/me/permissions`, thumbnails/`UploadResponse` fields, `/dashboard/stats`,
`/notifications`, `/groups`, the 5 link endpoints, or the env vars
`UPLOAD_THUMBNAIL_MAX_DIM` / `DASHBOARD_UPCOMING_DAYS`.

**Fix plan**: README-only edit — extend the bootstrap paragraph, add an
"Endpoints beyond CRUD" subsection and the two env vars. No code.

### F3 · LOW — `group.parent_id` / `ancestry` accepted unvalidated

`POST/PUT /groups` inserts `parent_id` without checking the parent belongs to
the caller's company (a foreign group id is accepted if it exists), and
`ancestry` is free client text rather than being derived from the parent chain.

**Fix plan**
- Files: `internal/db/queries/group.sql`, `internal/http/handler/group.go` (+ regen).
- Change: candidate-style guard — `parent_id` must resolve within
  `company_id` (reuse the link idiom: EXISTS check inside the INSERT/UPDATE, or a
  `FindGroupCandidate` pre-query → 404). Optionally compute `ancestry` server-side
  from the parent's `ancestry + '/' + id` and drop it from the DTO.
- Regression test: create group with a foreign `parent_id` → 404, nothing written.

### F4 · INFO — sixth m2m join table has no endpoints

`work_order_line_item_issues` exists in the schema but is not exposed.
`BACKEND-REQUIRED-WORK.md` P2 listed exactly five relationships, so this matches
the request — but confirm against the Django serializers whether the frontend
ever reads it.

**Fix plan (if wanted)**: mirror `service_entry_line_item_issues` — 4-query set
in `link.sql` (2-hop scope: line item → work order → company), store in
`link.go`, `LinkHandler` registration under `work-orders` module, doc stubs.

### F5 · INFO — WebP uploads never get thumbnails

`image/webp` is in the default upload allowlist but the stdlib cannot decode it,
so WebP images silently get no thumbnail (documented in `.env.example` and the
imaging package). Acceptable; if galleries fill with WebP, add
`golang.org/x/image/webp` (decode-only) to `imaging` — one import plus one map
entry.

## Remediation

Applied the same day, after review. Still uncommitted.

### F1 — fixed (61 columns across 31 resources)

Surveyed `information_schema` for every column carrying a non-zero default and
intersected it with the fields each `Create…Request` actually exposes: **58
columns over 30 tables**, plus 3 on the `vehicle` upsert. Every one of them wrote
a Go zero value over the schema default.

The fix is Go-side, in `internal/http/handler/defaults.go` — no SQL, so no query
regeneration:

| Kind | Treatment |
|---|---|
| `bool` (16) | request DTO field becomes `*bool`; `boolOrDefault(in.X, true)` — a pointer is required because `false` is meaningful and cannot otherwise be told from absent |
| `varchar` (36) | `orDefault(in.X, "OPEN")` — `""` is not a value these enum/label/colour columns accept |
| `integer` (6) | `int32OrDefault(in.X, 1)` |
| `numeric` (3) | `decimalOrDefault(in.X, 1)` |

`orDefault` already existed in `company.go` — session 1 had solved this for the
four `company` columns and for `asset_status.color_code`. It moved to
`defaults.go` and the other 30 resources now use it, so there is one helper set
rather than a second parallel idiom.

Swagger is unchanged by the pointer switch (`*bool` still renders as `boolean`),
so no client contract moved.

**Scope deliberately limited to create paths.** `PUT` is full replacement: a
client that omits a field is saying "unset it", and defaulting on update would
mean an omitted `state` silently reopening a resolved issue. That is a separate
design question, not this bug.

Verified live on a from-zero database: employee without `is_active` → active;
`"is_active": false` → still inactive; issue without state/source/asset type →
`OPEN`/`MANUAL`/`VEHICLE`; asset → `mi`/`OWNED`/`CAR`/`liters`; work order →
`PERCENTAGE`/`FIXED`; location → active; line item quantity → 1.
Unit tests: `internal/http/handler/defaults_test.go`.

### F3 — fixed

`internal/db/queries/group.sql` now resolves `parent_id` inside the caller's
company, in the write itself: `CreateGroup` inserts through a
`SELECT … WHERE parent IS NULL OR EXISTS(parent in company)`, and `UpdateGroup`
carries the same guard. No match → no row → `pgx.ErrNoRows` → **404**, the same
shape every other cross-tenant reference has. Worth noting the column has no
foreign key at all, so before this *any* integer was accepted.

`ancestry` is now derived from the parent (`parent.ancestry + '/' + parent.id`)
and was **removed from the create/update DTOs** — a caller able to set both could
describe a tree two contradictory ways. Update additionally refuses a parent that
is the group itself or one of its descendants, using a delimited-path
containment test, so the subtree cannot be cut into a cycle.

Verified live: root → `''`; child → `'1'`; grandchild → `'1/2'`; client-supplied
ancestry ignored; nonexistent parent, foreign-company parent, self-parent and
descendant-parent all 404 with nothing written; legitimate reparent and detach
still work.

*Known limitation, documented in the SQL:* re-parenting a group does not rewrite
its descendants' `ancestry`. That needs a subtree update this API does not
expose, and it is strictly better than the previous state, where the path was
whatever the client typed.

### F5 — fixed

`golang.org/x/image v0.44.0` added for its WebP decoder, and `image/webp`
blank-imported in `internal/platform/imaging`. WebP was already on the upload
allowlist, so the previous state was a gallery where WebP items alone fell back
to full-size originals. Output is still always JPEG, so only a decoder was
needed.

The test uses a real 60×40 lossless WebP embedded as base64 rather than a
synthesised header — a fake would pass while the import was missing. Verified
live end to end: uploading a `.webp` returns populated `thumbnail_*` fields and
the stored object is a genuine JPEG.
