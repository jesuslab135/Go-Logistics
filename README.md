# Go-Logistics (`fleet`)

A Go rewrite of a Django REST fleet-management backend. Clean-architecture layout
with a PostgreSQL persistence layer generated by [sqlc](https://sqlc.dev), an HTTP
API served with [Gin](https://gin-gonic.com), JWT auth, MinIO/S3 object storage,
and OpenAPI (Swagger) docs.

- **Language/runtime:** Go 1.26+
- **Database:** PostgreSQL 14+
- **Object storage:** MinIO (or any S3-compatible service)
- **Auth:** JWT (HS256 access + refresh), bcrypt passwords
- **Module path:** `fleet`

> Status: the full request pipeline is wired end-to-end. `companies` is exposed as
> a REST resource and `uploads` handles file/image storage; the other ~58 tables
> have domain structs + generated queries and follow the same handler template.

## Project layout

```
cmd/
  api/            HTTP server entrypoint (@swagger general info lives here)
  cli/            admin CLI (e.g. set an employee password)
docs/             generated OpenAPI spec (swag init output — do not hand-edit)
internal/
  config/         env-driven configuration
  auth/           JWT token service + bcrypt helpers
  db/
    migrations/   golang-migrate SQL (000001 schema, 000002 employee password)
    queries/      sqlc query sources (*.sql)
    gen/          sqlc-generated code (do not hand-edit)
    pool.go       pgx pool factory (registers the decimal codec)
  domain/         hand-written domain structs (one package per aggregate)
  http/
    dto/          request/response types
    handler/      Store implementations, auth handler, uploads, router, doc stubs
    middleware/   request id, logging, recovery, CORS, JWT auth
  platform/       apierr, paginate, filter, storage (local + minio), crud
```

## Run it locally (fresh laptop)

### 1. Prerequisites

- **Go 1.26+** — https://go.dev/dl/
- **Docker** — for Postgres and MinIO (or install them natively)
- **golang-migrate CLI** — to apply migrations:
  ```sh
  go install -tags 'postgres' github.com/golang-migrate/migrate/v4/cmd/migrate@latest
  ```
  (installs to `$(go env GOPATH)/bin` — make sure that's on your `PATH`)

### 2. Clone

```sh
git clone https://github.com/jesuslab135/Go-Logistics.git
cd Go-Logistics
go mod download
```

### 3. Start Postgres + MinIO

```sh
# PostgreSQL on host port 5433
docker run --name fleet-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=fleet \
  -p 5433:5432 -d postgres:16

# MinIO (S3 API on 9000, web console on 9001)
docker run --name fleet-minio -e MINIO_ROOT_USER=minioadmin -e MINIO_ROOT_PASSWORD=minioadmin \
  -p 9000:9000 -p 9001:9001 -d minio/minio server /data --console-address ":9001"
```

The app auto-creates the MinIO bucket (and sets a public-read policy) on startup.

### 4. Configure environment

```sh
cp .env.example .env
```

`.env.example` holds **three commentable blocks — DEV, QA, PROD**. Keep exactly one
uncommented; DEV is active by default and already points at the containers above.

### 5. Apply migrations

```sh
migrate -path internal/db/migrations -database "$DATABASE_URL" up
```

(Windows PowerShell: use `$env:DATABASE_URL` or paste the DSN inline.)

### 6. Run the API

```sh
go run ./cmd/api
# {"level":"INFO","msg":"http server listening","addr":":8080","env":"development"}
```

## Create the first user and log in

There is no public sign-up endpoint yet, and `/api/v1/*` requires a token, so the
first account is seeded directly in the database. Connect with
`docker exec -i fleet-pg psql -U postgres -d fleet` and run:

```sql
INSERT INTO company (name, tax_id, address, created_at, phone, email, website,
                     logo, city, region, postal_code, country, timezone,
                     currency, system_of_measurement)
VALUES ('Acme', 'ACME-001', '', now(), '', '', '', NULL, '', '', '',
        'MX', 'America/Mexico_City', 'MXN', 'metric');            -- id 1

INSERT INTO role (company_id, name, is_admin, permissions)
VALUES (1, 'Admin', true, '{}');                                  -- id 1

INSERT INTO employee (default_company_id, role_id, first_name, last_name,
                      employee_id, email, mobile_phone, work_phone, job_title,
                      license_class, license_number, license_state, street_address,
                      city, region, postal_code, country, updated_at)
VALUES (1, 1, 'Admin', 'User', 'EMP-001', 'admin@example.com',
        '', '', '', '', '', '', '', '', '', '', 'MX', now());
```

Set the password with the CLI, then log in:

```sh
go run ./cmd/cli setpass --email admin@example.com --password supersecret1

curl -X POST http://localhost:8080/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@example.com","password":"supersecret1"}'
# {"access_token":"...","refresh_token":"...","token_type":"Bearer","expires_in":3600}
```

Call a protected endpoint:

```sh
TOKEN=<access_token>
curl http://localhost:8080/api/v1/companies -H "Authorization: Bearer $TOKEN"
```

## Object storage (MinIO / S3)

Storage is abstracted behind a `Storage` interface with two backends, selected by
`STORAGE_BACKEND`:

- `local` — writes to `STORAGE_LOCAL_ROOT`, serves under `STORAGE_BASE_URL`.
- `minio` — any S3-compatible service (MinIO, AWS S3). The bucket is created on
  startup; with `STORAGE_MINIO_PUBLIC=true` an anonymous read policy is applied so
  object URLs work directly in `<img src>` tags.

Upload a file (multipart `file` field, requires a token):

```sh
curl -X POST http://localhost:8080/api/v1/uploads \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@./logo.png;type=image/png"
# {"key":"uploads/1/<rand>-logo.png",
#  "url":"http://localhost:9000/fleet/uploads/1/<rand>-logo.png",
#  "size":1234,"content_type":"image/png"}
```

The returned `url` is public and can be stored on a record (e.g. `company.logo`)
and rendered on the website. Keys are namespaced per tenant (`uploads/<company_id>/`)
with a random prefix so uploads never collide. For private buckets, the MinIO
backend also exposes `PresignedGetURL` for time-limited links.

For QA/PROD, point `STORAGE_MINIO_ENDPOINT` at your S3/MinIO host, set
`STORAGE_MINIO_USE_SSL=true`, and optionally `STORAGE_MINIO_PUBLIC_URL` to a CDN.

> **⚠️ `STORAGE_MINIO_PUBLIC_URL` must include the bucket.**
> `publicBase()` is asymmetric: when this variable is set it is used **verbatim**,
> while the endpoint fallback appends `STORAGE_MINIO_BUCKET` for you. So
> `http://cdn.example.com` yields `http://cdn.example.com/uploads/1/x.png` — no
> bucket — and every URL 404s/403s while uploads still return `201`. Set
> `http://cdn.example.com/<bucket>` instead. This bit us in `docker-compose.yml`
> (see `docs/KNOWN-ISSUES.md` #1): the failure is silent on the write path and
> only shows up as broken `<img>` tags in the client.

Note the local ports differ by how you start the stack: the `docker run` commands
above publish MinIO on **9000/9001**, but `docker-compose.yml` remaps it to
**9010/9011** (another project already holds 9000). `STORAGE_MINIO_PUBLIC_URL`
must match whichever you actually run.

| Method | Path                     | Auth | Description                    |
|--------|--------------------------|------|--------------------------------|
| GET    | `/healthz`               | no   | Liveness                       |

| PUT    | `/api/v1/companies/:id`  | yes  | Update                         |
| DELETE | `/api/v1/companies/:id`  | yes  | Delete                         |
| POST   | `/api/v1/uploads`        | yes  | Upload a file/image            |

## Development

Build / vet / format:

```sh
go build ./...
go vet ./...
gofmt -l .
```

Regenerate the sqlc layer after editing `internal/db/queries/*.sql` or the schema:

```sh
go install github.com/sqlc-dev/sqlc/cmd/sqlc@v1.29.0
sqlc generate
```

Regenerate the OpenAPI spec after changing handler annotations. Note the explicit
`-d` package dirs — swag's `go list` fails on directories without direct Go files
(the repo root, `internal/`), so the search dirs must be enumerated:

```sh
go install github.com/swaggo/swag/cmd/swag@v1.16.4
swag init -g main.go \
  -d ./cmd/api,./internal/http/handler,./internal/http/dto,./internal/auth,./internal/platform/storage \
  --parseDependency --parseInternal -o docs
```

Roll a migration back:

```sh
migrate -path internal/db/migrations -database "$DATABASE_URL" down 1
```
